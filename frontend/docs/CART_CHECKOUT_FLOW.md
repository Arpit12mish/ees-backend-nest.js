# Cart and Checkout Flow

## Guest Session ID

The cart is session-based. There is no user login required.

Session ID is managed in `src/lib/utils/session-id.ts`:

```ts
const SESSION_KEY = 'ees_guest_session_id';

export function getSessionId() {
  if (typeof window === 'undefined') return '';

  const existing = window.localStorage.getItem(SESSION_KEY);
  if (existing) return existing;

  const id = crypto.randomUUID(); // fallback to timestamp+random if unavailable
  window.localStorage.setItem(SESSION_KEY, id);
  return id;
}
```

- Uses `crypto.randomUUID()` if available, otherwise `guest-${Date.now()}-${Math.random().toString(16).slice(2)}`.
- The ID is stored in `localStorage` under `ees_guest_session_id`.
- On first visit the ID is generated and stored. On subsequent visits the same ID is retrieved.
- The ID is never sent as a cookie or header; it is passed in the JSON request body.
- Clearing localStorage or using a private/incognito window creates a new session ID and a new cart.

## Cart Event System

Cart state is shared across components using a custom DOM event.

- When any component modifies the cart (add, update, remove, apply coupon), it dispatches:
  ```ts
  window.dispatchEvent(new Event('ees-cart-updated'));
  ```
- `CartLink` (header) and `CartPage` listen for this event and re-fetch the cart:
  ```ts
  window.addEventListener('ees-cart-updated', refresh);
  ```
- This avoids a global state library while keeping the header count in sync.

## Add to Cart

`AddToCartButton` is a Client Component used on both `ProductCard` and the product detail page.

Flow:
1. User clicks "Add to cart".
2. Button shows "Adding..." and disables.
3. `addCartItem({ sessionId, productId, quantity: 1 })` posts to `POST /api/cart/items`.
4. On success, shows "Added to cart" and dispatches `ees-cart-updated`.
5. On error, shows the backend error message.

The backend validates stock and deduplicates items (adding the same product again increments its quantity).

## Cart Page

`/cart` is a Client Component. It loads the cart on mount:

```ts
useEffect(() => {
  getCart(getSessionId()).then(setCart).catch(() => setCart(null));
  window.addEventListener('ees-cart-updated', loadCart);
  return () => window.removeEventListener('ees-cart-updated', loadCart);
}, []);
```

### Update Quantity

1. User clicks `+` or `-` on a CartItem.
2. `updateCartItem(itemId, newQuantity)` patches `PATCH /api/cart/items/:itemId`.
3. Response is the updated cart; replaces state.
4. Dispatches `ees-cart-updated`.

### Remove Item

1. User clicks "Remove".
2. `removeCartItem(itemId)` sends `DELETE /api/cart/items/:itemId`.
3. Cart is re-fetched via `loadCart()`.
4. Dispatches `ees-cart-updated`.

### Coupon Validation

1. User enters a coupon code and clicks "Apply".
2. `validateCoupon(code, sessionId)` posts to `POST /api/coupons/validate`.
3. On success, cart is re-fetched. The `couponCode` field on the cart response shows the applied code.
4. Discount is reflected in `cart.discountAmount` and `cart.grandTotal`.
5. On error, the backend error message is displayed.

If the coupon is already applied, a "Remove" button appears beside the applied coupon code. Clicking it calls `removeCoupon(sessionId)` which sends `DELETE /api/coupons/:sessionId`, then re-fetches the cart. The coupon input is also cleared so a new code can be entered.

## Cart Summary

`CartSummary` displays:
- Subtotal
- Discount (negative, from `cart.discountAmount`)
- Shipping (`cart.shippingAmount`; 0 = Free, otherwise formatted as price)
- Grand Total

Shipping is free above ₹499. Below that, it is ₹49. These values are computed by the backend; the frontend displays whatever the backend returns.

## Checkout Flow

`/checkout` is a Client Component. It loads the cart on mount and renders a shipping form.

### Form Fields

All fields are required except Address line 2:
- Full name (`customerName`)
- Email (`customerEmail`)
- Phone (`customerPhone`)
- Address line 1 (`line1`)
- Address line 2 (`line2`, optional)
- City (`city`)
- State (`state`)
- Pincode (`pincode`)
- Country (`country`, defaults to "India")

### Submit Sequence

```
1. createOrder(input)           → POST /api/orders
2. createPayment(orderNumber)   → POST /api/payments/create
3. verifyPayment(orderNumber, mockPaymentId) → POST /api/payments/verify
4. dispatch ees-cart-updated (clears count)
5. router.push('/order-success?orderNumber=...')
```

All three backend calls happen sequentially in the same try/catch block. If any step fails, the error message is displayed on the form and the user can retry.

### Mock Payment Details

- `createPayment` creates a `Payment` row in `PENDING` status.
- The response includes `providerPaymentId` — a mock payment ID generated by the backend.
- `verifyPayment` sends this mock ID back to the backend, which confirms the order, decrements inventory, and clears the cart.
- The verify call is idempotent: if the order is already paid, it succeeds without decrementing inventory again.
- No real payment gateway is involved. No credit card details are collected.

## Order Success Page

After `verifyPayment` succeeds, the checkout page redirects to:
```
/order-success?orderNumber=ORD-YYYYMMDD-000001
```

The page reads `orderNumber` from the URL query string and displays it. It does not fetch the order from the backend. It shows a "Continue shopping" link back to `/products`.

## Backend Dependency Summary

| Step | Backend endpoint |
| --- | --- |
| Session ID | localStorage only, no backend call |
| Add to cart | POST /api/cart/items |
| Load cart | GET /api/cart/:sessionId |
| Update quantity | PATCH /api/cart/items/:itemId |
| Remove item | DELETE /api/cart/items/:itemId |
| Clear cart | DELETE /api/cart/:sessionId/clear |
| Apply coupon | POST /api/coupons/validate |
| Remove coupon | DELETE /api/coupons/:sessionId |
| Create order | POST /api/orders |
| Create payment | POST /api/payments/create |
| Verify payment | POST /api/payments/verify |

## Current Limitations

- Payment is mock-only. No real gateway (Razorpay, Stripe, PayU, etc.) is integrated.
- The checkout form has no client-side validation beyond HTML `required` attributes. Backend validation errors are displayed in a plain error message.
- There is no order lookup page. The order number is displayed on the success page but the user cannot look up their order history.
- The cart is not restored across devices since it is tied to `localStorage` on the current browser.
