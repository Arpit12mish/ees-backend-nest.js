What changed from the last status report in this project

  • The storefront is already deployed and serving real traffic on Vercel — an earlier status report in this project said otherwise. Confirmed via live response headers (server: Vercel, Next.js prerender headers) against https://enchantedenergystore.com.
  • The backend does not run on AWS App Runner, which is what was originally planned and guided. It runs on a bare EC2 instance behind nginx, with Let's Encrypt TLS and a custom RDS CA certificate trust file. This was discovered from response headers (Server: nginx/1.28.3 (Ubuntu)) and reverse DNS on the resolved IP (ec2-65-1-101-184.ap-south-1.compute.amazonaws.com), corroborated by two git commits ("Support EC2 IAM role for S3 uploads", "Configure trusted RDS TLS certificate").
  • Production already has real catalog data (82 products), meaning a data migration happened at some point after the last visible session state.

The one real gap found

  • No partner/admin-account management — there is no endpoint anywhere to create, list, or deactivate admin accounts. The only role values that exist are SUPER_ADMIN, ADMIN, EDITOR; accounts can only be created via prisma/seed.ts (env-var-driven, one fixed email) or direct database access.

Every admin section — Products, Categories, Collections, Coupons, Inventory, Orders, SEO, Reviews, Guides, FAQs, Services, Contact Leads, Analytics — has a matching backend route for every UI action, with correct role guards. The product create → image upload → publish → price-edit flow was tested live against the local environment end to end and worked correctly at every step. Contact Leads (src/modules/contact/admin-contact.controller.ts) was initially flagged here as missing — a first pass only searched src/modules/admin/** and missed that this controller lives in its own domain folder instead. Rechecked directly and confirmed live against the local backend before publishing; it works correctly.

Risks

High

Unpushed work is laptop-onlyHero Reels (full stack) plus five other modified files exist only in this working tree. A lost or wiped laptop loses them; nothing is recoverable from GitHub or production today.

High

No known way into production as an adminThe default dev credentials are rejected by production, and there is no account-management endpoint to create a new one remotely. Until this is resolved, nobody can use the admin dashboard against production even once it's deployed.

Medium

Deployment mechanism on EC2 is opaqueNo deploy script, systemd unit, or PM2 config is checked into the repo. How code actually reaches that box (manual SSH + git pull + restart, or something else) could not be determined from the repository alone.

Medium

TLS certificate expires Dec 21, 2026Let's Encrypt issued Sep 22. Whether certbot auto-renewal is configured on the EC2 box could not be verified from here.

Medium

Publish → storefront visibility has no floor below ~5 minutesNext.js ISR revalidates product listings every 300s and product detail every 600s, with no on-demand revalidation. A partner publishing a price change may reasonably expect it live sooner than that.

Info

Admin JWT sits in a JS-readable cookieNeeded today because both server components and client components read it. Not a CSRF risk — the backend only accepts the token via the Authorization header, never ambient cookie auth — but an XSS bug in the admin app would be able to read it. Standard trade-off for this app shape, worth knowing rather than fixing reflexively.

Flagged as unverifiable

Could not be confirmed from this environment. Not assumed either way.

Whether a working production admin account exists

The default dev credentials are rejected. That's consistent with either a different real account existing, or none existing at all — the API returns the same generic error either way, deliberately. No further login attempts were made, and npx prisma db seed was deliberately not recommended here — it runs the full prisma/seed.ts, which also upserts the entire demo catalog (categories, products, a coupon), not just an admin. Safe bootstrap procedure instead: a new script added this session, prisma/create-admin.ts, touches only the AdminUser table. Tested locally against the dev database before being recommended here. Once the backend update is deployed, SSH into the EC2 box and run:

ADMIN_EMAIL=you@yourdomain.com \
ADMIN_PASSWORD='a real strong password' \
npm run create-admin

Upserts by email, so it's safe to re-run even if that address already exists — it just resets the password. Change the password after first login if you like. Every account after this first one goes through the new Admin Accounts screen instead.
